# codex-usage v2.0.0

`v2.0.0` makes Codex session JSONL the sole token-accounting source. The release removes fragile cross-source authority rules and rebuilds the local ledger around replay-aware cumulative differencing. Per-machine attribution remains the signature entry point, while model, token-category, project, Thread, Session, Agent, local-day, and Standard API-equivalent-cost views provide broader explainable local usage analytics.

## Accounting changes

- Removed OTel ingestion, receiver-wide coverage suppression, and state-database `tokens_used` fallback. SQLite state data is used only for rollout discovery and metadata.
- Fixed fork/subagent rollouts whose child file replays parent history. The first `session_meta` now owns the physical file, `forked_from_id` identifies the copied prefix, and only the child continuation becomes new usage.
- Same-total corrections now update Input, Output, Cached Input, Cache Write, and Reasoning classifications across preceding events in the same cumulative segment instead of being discarded as duplicates.
- Truncated, same-size rewritten, or historically changed JSONL triggers a complete derived-index rebuild so stale events cannot survive.
- Ordinary Windows paths and `\\?\` extended paths normalize to one file identity.
- Every scan unions the Codex state index with `sessions/` and `archived_sessions/`, so a missing state row cannot hide a JSONL file.
- Local date and hour are persisted when an event is ingested, preventing later timezone changes from moving existing history between calendar buckets.

## Upgrade and compatibility

- Opening a pre-2.0 database upgrades the derived schema to v4, removes old OTel/state/parser output, and rebuilds from source JSONL. Source files are never modified.
- `codex-usage install` removes only the legacy exporter enclosed by codex-usage's own marker block. Third-party OTel configuration is left untouched, and Codex no longer needs to restart.
- The former `/v1/metrics` receiver is removed and now returns `404`.
- Existing JSON/CSV token fields and `/api/v1/*` routes remain available. `unattributed` is retained and always zero; status reports `accounting_mode: "jsonl_only"` and keeps `otel_active: false` for older clients.
- The API-equivalent cost remains an estimate based on local token categories and visible pricing coverage. It is not an OpenAI bill or account quota.

## Product and privacy

- README, Dashboard copy, Social Preview, screenshots, GIF, and bilingual videos now present codex-usage as explainable local usage analytics, with per-machine accounting as its distinctive feature rather than its only use case.
- The GitHub Pages Demo still uses synthetic session-only data, makes no external requests, sets no cookies, and reads no local files.
- The binary still never reads `auth.json`, prompts, replies, reasoning text, or tool output.
- Windows and Linux amd64/arm64 remain supported. macOS, cloud sync, account billing/quota, Homebrew, Scoop, and multi-tool aggregation remain out of scope.

## Downloads

Release assets include four single-file binaries for Windows/Linux amd64/arm64 and `SHA256SUMS`. Windows binaries are not code-signed, so SmartScreen may show a reputation warning; verify the SHA-256 checksum before running them.
